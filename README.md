# AstrBot 微信群管理插件 v1.6.0（wechat_agent 适配器）

适配 **`wechat_agent` 个人微信适配器**（由 `astrbot_plugin_wechat_agent` 提供，agent-wechat 守护进程方案）。

功能：

- **⏰ 定时艾特可视化配置**：WebUI 面板直接增删规则（群 / 每天或每周 / 几点 / 内容），保存即生效
- **📋 官方接龙引子**：发一条特定格式文本，微信客户端显示「参与接龙」，成员点按钮自行接龙；机器人只发起、不参与
- **🔄 命令 ↔ 面板双向同步**：聊天里创建/删除的任务与监控群自动写回配置面板，可视化管理
- **📇 群选项**：面板里可点选已发现的群；所有命令 `[群id]` 可省略（不带=当前群，带=指定群）
- **退群 / 入群监控**：多行明细播报（微信号 / 群昵称 / 时间），模板可自定义
- **群管理增强**：建群、改群名、拉人、踢人、退群、清群公告、改群内昵称、置顶会话、免打扰
- **只读查询**：群列表、群资料、群成员、联系人、守护进程能力
- **零第三方依赖**（纯 asyncio 调度），全部指令**仅 AstrBot 管理员**可用

> 说明：本插件**不含**自动发朋友圈能力。实测本机 `agent-wechat` 守护进程的 `capabilities` 中没有 SNS / moments 相关能力，相关 REST 路径全部 404，因此不做无法跑通的功能。

## ★ 定时艾特在哪里设置（WebUI 配置面板）

**路径：AstrBot WebUI → 插件管理 → 微信群管理 → 配置（齿轮）→ 找「⏰ 定时艾特规则」**

不用敲指令。面板里点「添加」新增一条规则，字段如下：

| 字段 | 填什么 |
| --- | --- |
| 启用 | 关掉可临时停用而不删除 |
| 群 ID | **可点选**下方「📇 已发现的群」里的群，也可填 `57418400291@chatroom`（`/群列表` 可查）；**留空的规则会被忽略** |
| **重复方式** | 下拉 `daily` = **每天**；`weekly` = **每周**，只按下面勾选的星期触发 |
| **周一 ~ 周日** | 7 个勾选框，默认勾周一~周五。`weekly` 时生效；一个都不勾 = 该规则不触发 |
| **几点艾特** | 只填 `HH:MM`，如 `09:30`；多个时间用英文逗号 `09:30,18:00` |
| 艾特谁 | `all` = @全体成员；`members` = @指定成员 |
| 指定成员 | `target=members` 时填 wxid 或群昵称，逗号分隔；用 `/群成员` 查 |
| 艾特内容 | 可多行，支持 `{date} {clock} {time} {weekday} {group}` |
| 备注 | 只给自己看，不发送 |

**常见配法**

| 想要 | 重复方式 | 星期勾选 | 几点艾特 |
| --- | --- | --- | --- |
| 每天早 9 点 | `daily` | 任意（不生效） | `09:00` |
| 工作日早 9 晚 6 | `weekly` | 周一~周五 | `09:00,18:00` |
| 每周一、三、五晚 8 点 | `weekly` | 周一 / 周三 / 周五 | `20:00` |
| 每周六上午 10 点 | `weekly` | 周六 | `10:00` |

- **面板是唯一数据源**：`/添加艾特任务`、`/添加艾特成员`、`/删除艾特任务` 都会把结果**回写到这里的规则列表**，
  `/艾特任务列表` 的序号就是面板里的规则序号。不再出现「命令加了但面板看不到」。
- **保存即生效**：AstrBot 保存插件配置时会自动热重载插件，无需手动重启。
- `/群管状态` 会显示规则数、展开的时间点数、监控群数、最近发送错误。
- 同一规则写多个时间点会展开成多条任务；旧写法 `mon-fri 09:00` 仍兼容（优先于星期勾选）。
- 旧版存在 KV 里的任务和监控群，升级后**自动迁移**到面板并清空 KV，不会丢。

> 热重载会重建插件实例。群会话映射存 KV，重载后可继续主动发消息；
> 但适配器客户端需要重新捕获，**保存配置后建议在目标群里发一条消息**，让直发通道恢复。
> 退群监控依赖这个客户端，未捕获时日志会提示「尚未捕获 wechat_agent 客户端」。

## ★ 发起官方接龙（实测可行路径）

**结论先说**：`agent-wechat` 守护进程**无法生成真正的接龙卡片**（微信内部是
`type=49 / appMessageType=53` 的 appmsg）。但微信客户端会对**特定格式的纯文本**
自动挂出「参与接龙」入口——插件只要发这条文本，成员就能点。

### 触发格式（实测）

```
📋 主题：
1. 首条内容
```

| 条件 | 必须 |
| --- | --- |
| 前缀 | `📋 ` |
| 标题 | 以中文全角 `：` 结尾 |
| 换行 | **LF `\n`**，不能是 CRLF `\r\n` |
| 列表 | `1. xxx` 编号列表，1 条或 2 条都行 |
| 结尾 | 不要多余换行 |

实测对照（本机消息库）：

| 消息 | 换行 | 结果 |
| --- | --- | --- |
| `📋 退群/入群监控列表：\n1. xxx（基线 3 人）` | LF | ✅ 显示「参与接龙」 |
| `📋 退群/入群监控列表：\n1. xxx\n2. xxx` | LF | ✅ 显示「参与接龙」 |
| 同上内容手动粘贴到微信输入框 | CRLF | ❌ 不触发 |
| `#接龙\n主题\n\n1. 测试项`（daemon `send_text`） | LF | ❌ 不触发，仍是 `type=1` 普通文本 |

`#接龙` 路线已实测排除：`POST /sends` 发出后消息库里是 `type=1 / appMessageType=null`，
没有生成 `type=49/app=53`。群里出现的真接龙卡片都是**成员在微信客户端点「参与接龙」**生成的。

### 用法

```
/发起接龙 周末聚餐报名
/发起接龙 周末聚餐报名 | 我报名
/发起接龙 53466925254@chatroom 周末聚餐报名 | 我报名
```

不带群 ID = 当前群。插件只发一条文本，之后**不监听、不统计、不参与接龙**。

### 面板定时发起

配置面板「📋 自动发起接龙」可增删规则：群、主题、首条内容、几点发起、
每天/每周勾选星期。`time` 留空 = 只用指令手动发起。

> 注意：机器人发的这条是**引子**，第一个点「参与接龙」的成员才是微信里接龙的创建人。
> 这是当前守护进程架构下唯一能做到的形式。

## ★ 群选项与监控群（面板可视化）

面板里新增三项，都在插件配置页：

| 配置项 | 作用 |
| --- | --- |
| **📇 已发现的群** | 插件收到群消息时自动把该群加入清单，供上方规则的群选择器点选。一般不用手动改 |
| **👥 退群/入群监控的群** | 多选要监控的群；`/监控退群 [群id]` 与 `/取消监控退群 [群id]` 会自动回写到这里 |
| **额外接收变动通知的群** | 单选；`/设置通知群 [群id]` 会回写；`/设置通知群 off` 清空 |

**所有命令的 `[群id]` 规则完全一致**：

```
/监控退群                          → 当前群
/监控退群 53466925254@chatroom     → 指定群
/添加艾特任务 09:30 打卡           → 当前群
/添加艾特任务 53466925254@chatroom 09:30 打卡 → 指定群
```

也接受完整会话 ID（`AstrBot娘:GroupMessage:53466925254@chatroom`），插件会自动取最后一段。

## 一、退群 / 入群播报

默认输出（WebUI 插件配置里可改 `leave_template` / `join_template`）：

```
张三 什么时候离开了本群
微信号：wxid_xxxxxxxx
群昵称：张三
退群时间：2026-11-05 16:20:07
```

入群同理，末行为「入群时间」。

### 模板占位符

| 变量 | 含义 |
| --- | --- |
| `{nickname}` | 群昵称（退群时取上一次成员快照） |
| `{wxid}` | 守护进程返回的成员 ID |
| `{group}` | 群 ID |
| `{time}` | `2026-11-05 16:20:07` |
| `{date}` / `{clock}` / `{weekday}` | 日期 / 时分 / 星期 |

**重要**：`{time}` 是**轮询检测到变动的时间**，不是微信服务器记录的精确退群时刻，
最多滞后一个轮询间隔（默认 5 分钟，配置项 `poll_interval_min`）。
`微信号` 字段实际是守护进程返回的成员 ID（wxid），不一定是用户自己设置的微信号。

### 启用监控

```
/监控退群                 # 当前群
/监控退群 12345678@chatroom
/退群监控列表
/取消监控退群
/设置通知群 <群id>         # 变动额外发到别的群
```

## 二、定时 @全体 / @指定成员（聊天指令方式）

> 更推荐用 WebUI 配置面板，见开头「★ 定时艾特在哪里设置」。
> 下面这节是**聊天指令**方式，两种方式可混用。

### 时间设置

| 写法 | 含义 |
| --- | --- |
| `09:30` | 每天 09:30 |
| `09:30,18:00` | 每天两次（一次添加生成多个任务） |
| `mon-fri 09:00` | 工作日（数字 `0-4` 等价，0=周一） |
| `mon,wed,fri 20:00` | 指定星期 |
| `mon-fri 09:00,18:00` | 工作日每天两次 |

### 自定义内容变量

`{date}` `{clock}` `{time}` `{weekday}` `{group}` — 发送时自动替换，可自由组合多行文字。

### 指令示例

```
/添加艾特任务 09:30 各位早安，记得打卡
/添加艾特任务 mon-fri 18:00 {date} 下班啦，今日复盘见文档
/添加艾特任务 09:30,18:00 该喝水了
/添加艾特任务 12345678@chatroom 12:00 午饭时间到

/群成员                    # 先查成员 ID 与群昵称（最多显示 40 条）
/添加艾特成员 09:30 wxid_aaa,wxid_bbb 该交周报了
/添加艾特成员 mon-fri 18:00 张三,李四 {date} 请提交日报
/立即艾特成员 张三,李四 测试一下

/艾特任务列表
/删除艾特任务 2
/立即艾特 测试一下@全体
```

成员可填 **wxid** 或 **群昵称**（插件会自动查成员列表解析；昵称支持包含匹配）。
`/艾特任务列表` 会标出每个任务是 `[@全体]` 还是 `[@成员 ...]`。

## 三、群管理增强

### 先查 ID

所有需要 `[群id]` 的指令，在群聊里发送时都可以**省略群id**（自动用当前群）。
在私聊里操作必须显式指定，用 `/群列表` 拿真实群 id：

```
/群列表                  # 显示群名 → 57418400291@chatroom
/群资料 [群id]           # 群名、群主、公告、成员数
/群成员 [群id]           # 成员昵称 → wxid
/联系人 [关键词]         # 已同步联系人的 wxid（建群/拉人用）
/群管能力                # 守护进程开放了哪些群变更能力、权限范围
```

群 id 形如 `57418400291@chatroom`。**成员参数请填 wxid**（`/群成员`、`/联系人` 箭头右侧那一串），
昵称只在能匹配到已同步成员/联系人时才会自动解析。

### 指令一览

```
/建群 wxid_a,wxid_b,wxid_c 项目讨论组     # 2~40 人，群名可选
/改群名 [群id] 新群名
/拉人 [群id] wxid_a,wxid_b               # 最多 40 人
/踢人 [群id] wxid_a,wxid_b               # ⚠ 需二次确认
/退群 [群id]                             # ⚠ 需二次确认
/清群公告 [群id]                         # ⚠ 需二次确认
/改群内昵称 [群id] 小助手
/置顶会话 [群id] on        /置顶会话 [群id] off
/免打扰 [群id] on          /免打扰 [群id] off
```

`on/off` 也可以写 `开/关`、`1/0`、`true/false`。

### 二次确认（默认开启）

对 `/踢人`、`/退群`、`/清群公告` 这三类不可逆操作，指令发出后不会立即执行，而是返回：

```
⚠️ 待确认操作
操作：踢人（2 人）
目标群：57418400291@chatroom
将移出：wxid_a, wxid_b
请在 60 秒内发送 /确认群管 执行，或 /取消群管 撤销。
（仅本人可确认，超时自动作废）
```

- **仅发起人本人**可确认（`get_sender_id()` 为准）
- 超时自动作废，配置项 `confirm_ttl_sec`（默认 60 秒，10~600）
- 可在 WebUI 关掉 `require_confirm` 关闭确认（不建议）

### 权限要求

守护进程 `capabilities` 标注：

```json
{
  "groupMutationScope": "admin",
  "groupCreateMinSelectedMembers": 2,
  "groupMutationMaxSelectedMembers": 40,
  "groupMutations": ["create", "rename", "leave", "add_members",
                     "remove_members", "my_name", "clear_announcement"],
  "threadPinningScope": "admin",
  "threadNotificationTargets": ["direct", "group"]
}
```

即**机器人微信号必须是群主或管理员**。插件侧另有一层 AstrBot `PermissionType.ADMIN` 保护。
用 `/群管能力` 可随时查看当前守护进程实际开放的能力。

### 执行结果与排障

群变更是异步的：提交后返回 HTTP 202 + operation，插件自动带 `Idempotency-Key` 并轮询
`GET /v1/accounts/{id}/operations/{op}` 直到终态（默认最多等 30 秒，配置项 `mutation_wait_sec`）。

- `✅ … 执行成功` — operation 到达成功终态
- `❌ 操作失败（HTTP 409 / group_contact_unavailable）` — 群不存在或联系人缓存未同步，用 `/群列表` 核对群 id
- `⏳ 已提交但 N 秒内未收到终态` — 不代表失败，可能仍在微信端排队，稍后用 `/群资料` / `/群成员` 核对

常见错误码在插件里已翻译成中文提示（如 `invalid_group_members`、`invalid_group_text`、
`admin_required`、`auth_required`、`needs_review` 等）。

## 使用前必读

1. **先在要管理的群里发一条消息**：插件从消息里抓 `event.platform.get_client()`，没抓到时监控与群管理都不可用（`/群管状态` 可查）。
2. **@全体 / 群变更需要群主或管理员**；无权限时守护进程会拒绝（`/群管能力` 可看 scope）。
3. 退群监控是**轮询差比**，无法区分「主动退群 / 被踢」；首次启动建立基线，不会误报全员入群。
4. 成员列表为空时跳过该轮，避免误报「全员退群」。
5. `/退群` 会让机器人真的退出群且**无法自动加回**，务必保留二次确认。
6. 所有群变更指令都会写入 AstrBot 日志（不含 token），便于回溯。
7. **保存插件配置会触发热重载**：规则即时生效，但适配器客户端需重新捕获，建议在群里发一条消息。
8. 群会话映射、监控基线存 KV；热重载不丢。待确认的破坏性操作会因重载而作废，需重新发起。

## 实现说明（wechat_agent 实测 API）

| 能力 | 接口 |
| --- | --- |
| 客户端 | `event.platform.get_client()` → `WeChatClient` |
| 拉成员 | `await client.group_lookup(thread_id)`，为空回退 `group_members()` |
| 只读查询 | `GET v1/accounts/{a}/groups`、`/groups/{id}`、`/contacts`、`/capabilities` |
| 群变更 | `client.request(method, client._acc(suffix), json_body=..., headers={"Idempotency-Key": ...})` |
| 结果轮询 | `client.operation(op_id)` → `GET v1/accounts/{a}/operations/{id}` |
| @全体 | `AtAll()` → 适配器转 `mentions.all=true` |
| @指定成员 | `At(qq=wxid)` → 适配器转 `mentions.userIds` |
| 发送 | `await adapter.send_chain(thread_id, MessageChain)`，兜底 `context.send_message(umo, ...)` |
| 持久化 | `put_kv_data` / `get_kv_data` |

群变更端点（全部用不存在的群 id 做过安全探测，确认 405/403/422 均不出现）：

| 操作 | 方法 / 路径 | 请求体 |
| --- | --- | --- |
| 建群 | `POST /groups` | `{"members": [...], "name"?: "..."}` |
| 改群名 | `PATCH /groups/{id}` | `{"name": "..."}` |
| 拉人 | `POST /groups/{id}/members` | `{"members": [...]}` |
| 踢人 | `DELETE /groups/{id}/members` | `{"members": [...]}` |
| 退群 | `POST /groups/{id}/leave` | `{}` |
| 清群公告 | `DELETE /groups/{id}/announcement` | `{}` |
| 改群内昵称 | `PUT /groups/{id}/my-name` | `{"displayName": "..."}` |
| 置顶会话 | `PUT /threads/{id}/pin` | `{"pinned": true\|false}` |
| 免打扰 | `PUT /threads/{id}/notifications` | `{"muted": true\|false}` |

适配器不推送群成员变动事件，所以退群检测只能轮询差比。

## 已知限制

- 退群/入群时间为检测时间，非精确时刻；无法区分主动退群与被踢。
- 部分微信版本 `group_lookup` 可能返回不全，插件会跳过空结果并告警。
- `/联系人` 只显示守护进程已同步的联系人，同步不完整时昵称解析会失败，请直接填 wxid。
- 适配器自带发送节流（默认每条间隔 2~4 秒、每分钟 12 条），批量通知自动排队。
- 单次群变更成员数上限 40（守护进程限制），建群至少 2 人。
- 朋友圈相关能力在当前 `agent-wechat` 架构下不可用。
- 守护进程**不能直接创建微信官方接龙卡片**（`type=49/app=53`）。插件改用「格式文本引子 + 成员点击」的方式，见「★ 发起官方接龙」。真接龙卡片只能由微信客户端 UI 交互产生。
- 配置面板里群 ID 留空的规则会被忽略；面板任务不会出现在 `/艾特任务列表` 中。
